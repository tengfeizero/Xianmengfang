# PRD — 现梦坊（codename: xianmengfang）

> 状态：v0.2，项目名与技术栈已定稿，其余待定项见第 9 节。
> 命名含义：现梦坊 —— 让创意（梦）走进现实（现）。
> 模式定位：单厂部署（一套系统服务一个工厂），架构预留多租户扩展空间。

---

## 1. 一句话定义

用户在小程序里创作作品（AI 生成 / 照片转风格 / 元素拼装），把作品图案应用到工厂商品（服饰/周边/玩偶）上，下单购买；工厂在 Web 后台接单生产、发货。

## 2. 角色与端

| 角色 | 端 | 主要操作 |
|---|---|---|
| 消费者 | 微信小程序 | 登录、创作、管理作品库、选商品、下单、支付（MVP 为模拟支付）、确认收货、查看订单 |
| 工厂管理员 | Web 网页后台 | 管理商品（分类/规格/价格，后台可配置）、管理元素素材库、处理订单（接单/发货/填单号）、管理用户、查看 AI 用量 |

## 3. 消费者核心流程（MVP 最小闭环）

```
登录 → 进入创作工坊 → 三种创作方式任选 → 保存作品 → 选商品 → 选作品图案 → 下单 → 支付(模拟) → 管理员接单/发货 → 用户确认收货
```

### 3.1 创作工坊（三种方式）

1. **元素拼装**：预设小姑娘底板 + 分类元素（帽子/睫毛/头发/表情/服饰等），固定槽位换装 + 可微调位置缩放，最终合成为一张作品图。
2. **文字生成图**：输入描述 → 调 AI 生图 API → 生成插画作品。
3. **照片转风格**：上传手机拍摄照片 → AI 转指定风格插画作品。

- 作品保存到个人作品库，可删除、可设为"可用于商品"。
- AI 调用需要消耗额度，MVP 阶段按"每人每日限免 N 张"控制成本。【待定：N 的数值】

### 3.2 商品与下单

- 商品：服饰类、周边类、玩偶类；分类、规格（尺码/颜色等）、价格、库存均由后台配置。
- 下单 = 选商品 SKU + 绑定一个作品图案 + 数量。
- **支付：MVP 用模拟支付**（原因见第 6 节资质约束），下单即到"待发货"；真实微信支付待资质齐备后替换，支付模块预留接口。

### 3.3 订单状态机

```
待支付(模拟支付则跳过) → 待接单 → 待发货 → 已发货 → 已完成(确认收货)
                      ↘ 已取消
```

## 4. 管理后台（Web）

- 登录（管理员账号密码，密钥/密码不写死在代码里）
- 商品管理：分类、SPU/SKU、价格、库存、上下架
- 素材管理：拼装元素上传（分类、PNG 图层素材）、底板管理
- 订单管理：列表/详情、接单、发货（填物流单号）、退款标记（MVP 仅标记，不做退款流）
- 作品审核（可选开关）：管理员可下架违规作品【待定：MVP 是否需要】
- AI 用量看板：调用次数、费用估算

## 5. 技术方案（已定稿 2026-11-06）

- **后端**：Go（Gin + GORM），数据库 SQLite 起步，后期迁 PostgreSQL；MQ/Redis/ES 等暂不引入，按需再说。
- **前端**：微信小程序（原生）+ Web 管理后台（Vue 3 + TS + Element Plus）。
- **部署**：待采购云服务器（Linux）+ 域名 ICP 备案；小程序要求 HTTPS + 备案域名。
- **AI 生图**：先接低价/免费额度国内 API，生图能力封装为独立 service，换厂商不动业务代码；密钥只走环境变量。

## 6. 资质与合规约束（重要，你需要提前准备）

1. **你目前是个人主体小程序**：个人主体不能开通微信支付，也不适合电商类目。MVP 用模拟支付开发；上线收款前需要注册个体户/企业主体小程序 + 微信支付商户号。
2. **服务器 + 域名**：需购买云服务器与域名并完成 ICP 备案（小程序要求 HTTPS + 备案域名），备案约 1-2 周，建议现在就启动。
3. **AI 生图密钥**：由你注册并付费，密钥只进服务器环境变量，绝不进代码仓库。
4. 内容安全：用户上传照片与生成作品需过微信内容安全校验（msgSecCheck/imgSecCheck）。

## 7. MVP 边界（明确不做）

- 真实微信支付（资质齐备后做）
- 多租户/SaaS 化（仅架构预留）
- 退款/售后流程、物流跟踪详情、评价体系
- 元素自由拖拽拼贴（仅做固定槽位 + 微调）

## 8. 验收口径（最小闭环）

一条链路可演示：新用户登录 → 拼装一个作品 → 选一件商品绑定该作品 → 下单 → 后台接单发货 → 用户确认收货，订单状态流转与数据全部正确。
