# 与 AI 协作开发流程（现梦坊项目版）

> 骨架源自「货本 StockBook」项目（v0.1 → v0.25，单人 + AI 完成 6 个里程碑、25 个版本）的通用实践，
> 已按现梦坊的实际技术栈、目录结构与已踩过的坑落地调整。
> 本项目 v0.1 → v0.6（M0 竖切 → M1 全量）即按此流程执行。

---

## 一、先明确一件事：AI 不是"自动完成"，是"高速执行"

协作顺畅的项目都有一个共同点：**人负责判断，AI 负责执行**。一旦把判断也交出去，返工率会立刻上升。

| 角色 | 人（你） | AI |
|---|---|---|
| 需求 | 决定做什么、不做什么、优先级 | 拆解为可验收的任务 |
| 设计 | 拍板架构取舍、数据模型边界 | 给出 2-3 个方案与代价，按选定方案落地 |
| 实现 | 抽查关键逻辑 | 写代码、写测试、跑构建 |
| 验收 | **亲自确认业务正确性** | 提供可执行的证据（命令输出、截图、断言） |
| 交付 | 决定发布时机、面向客户的话术 | 更新文档、打包、提交 |

**人必须亲自做的 5 件事**（不能外包给 AI）：

1. 业务规则对不对（订单金额、库存扣减、订单快照算得对不对）
2. 安全底线（密钥、权限、公网暴露、支付资质）
3. 真实环境验证（微信开发者工具/真机、真实 appid 与支付）
4. 产品取舍（这个功能要不要做、做成什么样）
5. 对客户的承诺（卖给工厂的交付标准）

## 二、项目冷启动：一次性把"地基"打好

本项目已完成冷启动（2026-11-06），以下记录的是实际做法，供回溯与延续。

### 1. 文档体系（已建成，全部在 docs/）

| 文档 | 作用 | 维护约定 |
|---|---|---|
| `PRD.md` | 做什么、给谁用、边界在哪、资质约束 | 人定稿，AI 补细节 |
| `DATA-MODEL.md` | 表、字段、**订单状态机**、金额/库存口径 | AI 起草，人审核口径 |
| `API.md` | 接口契约（路径/参数/错误码/实现状态） | AI 维护，改接口必须同步 |
| `CONVENTIONS.md` | 代码纪律：**目录结构与落位决策表**、分层、金额单位、事务边界、前端红线 | 人定一次，AI 每次遵守 |
| `CHANGELOG.md` | 每个版本改了什么、为什么 | AI 每轮追加，**它是进仓库的"现状快照"** |
| `TODO.md` | 已完成 / 下一步候选 / Backlog | AI 维护，人调整优先级 |
| `用户手册.md` | 面向工厂管理员/消费者的操作说明 | **待建**（上线前 M2 补） |

> 经验：`CONVENTIONS.md` 是投入产出比最高的一份。本项目写清了"业务规则只允许写在 service 层""金额一律用分""库存原子扣减（`UPDATE ... WHERE stock >= ?`）""订单状态变更必须记 order_events 且只追加"，从 M0 到 v0.6 没有在这些口径上返过工。

> 目录规范同样写进 `CONVENTIONS.md`（"目录结构"一章）：三端完整目录树 + **新增文件落位决策表**（新接口 / 新表 / 新配置 / 新管理页 / 新小程序页 / 跨页组件 / 一次性脚本各放哪，以及要同步哪份文档）+ 5 条目录红线。它压缩的是 AI 的自由度：v0.7 重构前根目录曾出现 `login.yaml`、`orders.yaml`、`shots/` 等测试残留，根因不是马虎，而是**没有落点规则，AI 就按"当下最方便"放**。写了决策表之后，"这个文件放哪"不再需要每次问。

### 2. AI 行为约束（AGENTS.md，仓库根目录）

AI 每次会话自动读取，只放硬规则。本项目实际内容（摘要）：

```markdown
# 项目规则（现梦坊）
- 技术栈：Go（Gin + GORM + glebarez/sqlite 免 CGO）+ SQLite（后期迁 PG）；Vue 3 + TS + Vite + Element Plus；微信小程序原生
- 分层：api 只做参数绑定，repo 只做 CRUD，业务规则全部在 service
- 金额一律 int 分，禁止 float；库存原子扣减；订单状态机只允许在 service 层流转
- AI 生图走 Provider 接口（当前 Mock），厂商实现可替换，业务代码不感知
- 每次改动必须：go vet + go test 通过；小程序改动 node --check + 开发者工具重编译
- 改完同步 docs/ 对应文档；不得提交 server/data/、*.db、任何密钥
```

### 3. 最小闭环（M0，已完成）

不做十个模块，先做一条能跑通的竖切：
**登录 → 看商品 → 下单（mock 支付）→ 后台接单 → 发货 → 确认收货**。
跑通后 M1 的创作工坊、AI、作品库，以及 v0.6 的地址管理，全部是往这条骨架上加肉。

### 4. 可验证的演示数据（本项目的形态）

- 内置演示数据：管理员 `admin/admin123`、3 分类 / 4 商品 / 6 SKU、小姑娘底板 + 6 类拼装元素（程序化生成 PNG）
- **三套回归脚本就是"演示数据 + 验收"的合体**（`server/scripts/`）：
  - `m0_e2e.py`：登录→下单→接单→发货→确认收货，金额库存对账
  - `m1_e2e.py`：素材→拼装合成→上传→AI→配额 429→作品库→下单绑作品
  - `mp_e2e.py`：模拟小程序完整调用链（含地址管理与下单快照断言）
- 每轮改动后跑这三套脚本 + 单测，即完成机器可验证的回归

## 三、每个迭代的标准循环（10 步）

**每一步都有明确的产出物和验收动作**，缺一步就会在下一轮还债。
真实案例：v0.6 地址管理就是按这个循环走完的（后端 CRUD+单测 → 小程序两页 → 三脚本回归 → 文档 → commit `ceb92a9`）。

```
① 读现状 → ② 定范围 → ③ 拆任务 → ④ 后端 → ⑤ 编译
                                              ↓
⑩ 记忆 ← ⑨ 提交 ← ⑧ 文档 ← ⑦ 清理 ← ⑥ 前端 + 实测
```

### ① 读现状（不读不改）

- 明确要改的文件、相关调用方、数据结构
- 大文件用检索定位（grep 关键函数/字段），不要整文件灌进上下文
- 让 AI 先复述"现在的行为是什么"，确认无误再动手

> 反例：直接说"给下单加个地址"。AI 可能凭空发明字段。
> 正例："先读 order.go 的 Create 和 handlers.go 的 orderCreate，说明现在下单的参数与事务边界。"

### ② 定范围（一次一个功能）

一个迭代 = 一个可独立验收的功能（vertical slice），包含后端 + 前端/小程序 + 文档 + 实测。
**不要**一个迭代塞三个功能，也不要"后端全写完再统一做前端"——中间态无法验收。

### ③ 拆任务（写下来，别记在脑子里）

用任务清单把功能拆成 3-6 个可勾选步骤，每步有完成标准。以 v0.6 地址管理为例：

```
[x] 后端：Address 模型 + AddressService（默认唯一/上限20/软删补位）+ 下单快照
[x] 后端：/addresses CRUD + 设默认接口 + 7 组单测
[x] 小程序：地址列表/编辑页、商品页地址卡、订单页展示收货人
[x] 实测：三套 e2e 更新为带地址下单，全链路通过
[x] 文档：API / DATA-MODEL / CHANGELOG / TODO
```

### ④ 后端实现

顺序：模型/迁移 → service（业务规则 + 事务）→ api（薄层）→ 路由与权限 → 单元测试。
**业务规则先写成测试**，再实现。本项目实测有效：SKU 删除保护的 bug 就是单测抓到的（见第七节坑表）。

### ⑤ 编译与静态检查（不通过不往下走）

```bash
cd server && go vet ./... && go test ./...
```

这一步是廉价的门禁。跳过它，问题会在前端联调时以"接口 500"的形式花十倍时间暴露。

### ⑥ 前端/小程序 + 检查 + **实测**

```bash
cd web && npm run build          # vue-tsc 严格类型检查 + 构建
cd miniprogram && node --check 所有 *.js   # 小程序语法门禁
```

然后必须**真的跑起来验证**，而不是"看代码觉得没问题"：

| 验证方式 | 适用 | 本项目实例 |
|---|---|---|
| Python 脚本断言 JSON | 接口逻辑、权限、错误码、对账 | `server/scripts/*.py` 三套回归 |
| 临时端口 + 临时库 | 不污染开发数据，可反复重置 | `XMF_DB=data/test_xx.db XMF_ADDR=:18080` |
| Edge 无头浏览器截图 | Web 后台布局、遮挡、交互 | M1.4 登录→接单→发货→四管理页 |
| 微信开发者工具 | 小程序页面、交互、弹窗 | 地址编辑、canvas 拼装手感 |
| 手工点一遍主流程 | 交互手感、文案、异常提示 | 用户每次验收 |

> 本项目实例：地址编辑页"详细地址无法填写"就是手工验证发现的问题——纯代码审查看不出来。

### ⑦ 清理

- 关掉临时进程（TaskStop）、删除临时库与测试二进制
- 删除测试残留物（截图、快照 yaml、浏览器会话目录）——本项目曾发生 `login.yaml` 残留根目录
- 确认没有把测试数据、密钥、备份文件留在工作区

### ⑧ 文档同步（和代码同一次提交）

| 改了什么 | 必须同步 |
|---|---|
| 新功能 | CHANGELOG（版本+日期+要点）、TODO 勾选 |
| 接口变化 | API.md（含"接口变更"标注，如 v0.6 下单必传 address_id） |
| 表/字段/状态机 | DATA-MODEL.md |
| 用户可见行为 | 用户手册（待建） |
| 部署方式 | README |
| 技术决策与踩坑 | 记忆（见第 ⑩ 步） |

**单一事实来源**：同一份内容只写一处，其他地方引用。例如订单状态机只在 DATA-MODEL.md 定义，API.md 与代码注释引用它，不在三处各写一份。

### ⑨ 提交（一个功能一个 commit）

```
feat(v0.6): 收货地址管理——用户端 CRUD + 下单快照
fix(小程序): 地址编辑页详细地址无法填写——textarea 原生组件遮挡改为 input
docs: PRD 补记收货地址需求（3.2 下单流程与角色表）
```

提交信息写"为什么"，不只写"改了什么"。半年后回看，只有"为什么"还有价值。

### ⑩ 记忆（写给下一次会话的自己）

两层分工：

- **`.workbuddy/memory/`（本地日记，不入库）**：当日决策、踩坑、临时结论，AI 每轮迭代追加
- **`docs/CHANGELOG.md` + `TODO.md`（进仓库）**：正式的现状快照——版本、决策、坑、待办四块，每轮同步

> 判断标准：如果新会话（或换一台机器上的另一个 AI）只能看到"仓库 + 当前代码"，它能不能在 10 分钟内接着干？能——因为 CHANGELOG 记了每个版本"为什么"，AGENTS.md 定了规矩，TODO 标了下一步。
> 本地日记只当草稿，**进仓库的才算数**。

## 四、让 AI 输出可靠的四条硬规则

### 1. 给约束，不给愿望

| 愿望（不可验收） | 约束（可验收） |
|---|---|
| "把创作工坊做好一点" | "拼装参数（x/y 为 0~1 相对坐标、scale 倍率）前端预览与服务端合成同一套口径，合成 PNG 尺寸与底板一致" |
| "AI 生图做好点" | "Provider 接口隔离厂商；每日配额读 configs 表（后台可改），超限返回 429 与人话提示" |
| "注意安全" | "JWT 密钥无环境变量时生成随机值持久化；上传白名单 jpg/png/webp ≤10MB + 路径越界校验；密钥不进代码" |

### 2. 要求证据，不接受"已完成"

AI 说"已完成"没有信息量。要求它给出：命令 + 输出 + 关键截图 + 边界情况的结果。
本项目惯例：每个迭代收尾都带"验收证据"段（单测清单、e2e 输出、对账数字、截图）。

### 3. 出错时先复现，再定位根因

标准动作：复现 → 缩小范围 → 找到根因 → 修根因 → 补一个能挡住它的测试。
本项目真实案例：`skuid` 列名 bug，表面是"删除保护没生效"，根因是 GORM 把 `OrderItem.SKUID` 推导成 `skuid` 列，`WHERE sku_id` 静默匹配不到——修的是显式列名，并留下单测挡住回归。

### 4. 一次只让 AI 改一个关注点

同时改 5 个文件 + 顺手重构 + 顺便升级依赖 = 出问题时无法二分定位。
要重构就单独一个迭代，重构期间不加功能。

## 五、上下文与长会话管理

AI 的上下文会满，长项目必须主动管理：

- **一个会话一个主题**：做地址管理就只谈地址，别混着聊支付
- **会话开头给"现状摘要"**：当前版本、已完成项、这次要做什么、相关文件路径
- **大文件用检索**：grep 定位函数，读 50 行而不是读 2000 行
- **上下文将满时主动收口**：先提交、写记忆，再开新会话（本项目已发生多次 compaction，均靠此条无损续接）
- **记忆分层**：本地 `.workbuddy/` 日记（草稿）+ 仓库内 CHANGELOG/TODO（正式快照），见第 ⑩ 步
- **入口约定进仓库**：`AGENTS.md` 在仓库根目录，新代理自动读到硬规则、禁区、门禁命令

> 现状快照的换代时机：CHANGELOG 超过 30 条后，可新增 `docs/项目现状.md`（版本/决策/坑/待办四块）作为精简入口，CHANGELOG 退为流水档案。

## 六、验收清单（每个迭代复制一份）

```markdown

### 功能
- [ ] 主流程走得通（路径：______）
- [ ] 边界：空数据 / 超量（库存不足、配额用尽）/ 无权限（他人资源 403）/ 已下架
- [ ] 错误提示是人话，不是 "500 internal error"

### 数据
- [ ] 订单金额 = SKU 价格 × 数量（分），与前端展示一致

- [ ] 订单快照（金额、SKU 规格、收货信息）与下单时刻一致，后续改动不影响

### 工程
- [ ] go vet / go test 通过
- [ ] npm run build（vue-tsc）通过；小程序 node --check + JSON 校验通过

- [ ] 未提交 server/data/、*.db、密钥、日志、测试截图

### 文档
- [ ] CHANGELOG 记了版本与要点
- [ ] API / DATA-MODEL 已同步；PRD 若涉需求变化已补记
- [ ] TODO 勾选并更新下一步

### 交付
- [ ] 本地服务重启后真实可用（8080：/api + /ui/）
- [ ] 提交信息说明了"为什么"
- [ ] 记忆已追加
```

## 七、常见坑（通用 + 本项目已踩过的）

| 坑 | 表现 | 对策 | 本项目实例 |
|---|---|---|---|
| ORM 字段名推导错误 | 列名变 `skuid` 而非 `sku_id`，WHERE 静默失效 | 关键字段显式 `gorm:"column:..."` | v0.4 SKU 删除保护失效，单测抓到 |
| go run 缓存 | 改了代码服务行为不变 | 改完必须重启；联调期用 `go build` 产物 | M1 素材路径修复后误判未生效 |
| 本地代理干扰 | curl 访问本机端口返回 502 | `--noproxy '*'` | 全程惯例 |
| 编码 | GBK 终端 curl 发中文乱码，误判为产品 bug | 用 Python 脚本发请求 | M0 发货"顺丰"乱码 |
| 后台进程随 shell 退出 | 测到一半服务没了 | 任务托管，别用 `&`；浏览器会话不跨命令存活 | playwright 需单命令跑完整流程 |
| 原生组件层级 | 小程序 textarea 被遮挡/点击错位 | 单行场景用 input + cursor-spacing | v0.6 地址详址无法填写 |
| 忘带环境变量 | `/ui/` 404 以为前端坏了 | 启动命令固定化，检查启动日志 | XMF_WEB 未设置 |
| 素材路径不一致 | 数据库存 `elements/x.png`，文件生成到别处 | 生成与入库用同一常量拼接路径 | M1 元素 404 |
| 外部工具不可用 | 脚手架模板哈希错误 | 降级预案提前想好，偏差记入 CHANGELOG | 小程序脚手架×2 失败，手工搭建 |
| 旧库与新迁移不兼容 | 旧库列名错，新代码查询异常 | 结构性变更后备份重建开发库 | xmf.db 备份后重建 |
| 文档漂移 | 文档说的和代码做的不一致 | 文档同步纳入提交清单 | 每轮惯例 |
| 默认弱密钥 | 仓库里带着 `admin123` | 仅限本地演示数据；上线前改密（已记 PRD 第 6 节） | 待办跟踪中 |

## 八、反模式（看到就该停）

1. **"帮我把这个项目做完"**——范围太大，AI 会自己编需求，产出不可验收
2. **一次改十个文件**——出问题无法定位，review 也看不过来
3. **只看代码不运行**——AI 和你都会"觉得没问题"，一跑就崩
4. **用 `any` / 跳过类型检查**——把编译期错误推迟到用户面前
5. **文档最后统一补**——最后一定不会补，或者补的和代码不一致
6. **让 AI 决定产品边界**——它会倾向于"都做"（例如擅自加退款资金流、加多租户），导致什么都做不深；边界变化必须人拍板并回写 PRD
7. **不写记忆就开会话**——下一个会话从零开始，重复踩同样的坑

## 九、怎么判断这套流程在起作用

三个可观察的指标（不需要工具，靠自己感知）：

| 指标 | 健康值 | 本项目现状 |
|---|---|---|
